# Локальный музыкальный плеер

Этот проект создан в качестве альтернативы имеющимся плеерам которые не предоставляют необходимой возможности импорта музыки и минималистичночти интерфейса 

## Особенности проекта

- **Минималистичный дизайн**: Стильный, чистый интерфейс без лишних деталей, плавная плавающая навигация и поддержка тёмной/светлой тем.
- **Удобный импорт музыки**: Сканирование локальных каталогов через Android Storage Access Framework (SAF) с рекурсивным поиском файлов и быстрым кешированием метаданных в Room SQLite.
- **Интеллектуальное воспроизведение**:
  - Автоматическая пауза при входящих/исходящих звонках и возобновление проигрывания сразу после завершения вызова (Audio Focus).
  - Плеер с интерактивной вращающейся виниловой пластинкой, автоматически извлекающий обложки треков.
  - Интеграция с системной медиа-сессией (Media Session) для управления с экрана блокировки и шторки уведомлений.
- **Современный стек технологий**: Kotlin, Jetpack Compose, Room Database, Coroutines & Flow, MVVM-архитектура.

## Требования для сборки

- **Java Development Kit (JDK)**: Версия 17
- **Android SDK**: API level 24 (minSdk) / API level 36 (targetSdk)
- **Среда разработки**: Android Studio Koala / Ladybug или новее
- **Система сборки**: Gradle 8.x+ (используется Gradle Kotlin DSL `.gradle.kts`)

## Внешний Broadcast API (текущий трек)

Приложение постоянно оповещает внешних слушателей о текущем треке через широковещательное
сообщение с action:

```
erech14.freemusical.app.action.TRACK_STATE
```

Сообщение отправляется **неявно** (`sendBroadcast` без указания пакета), поэтому его может
принимать любое приложение.

### Когда отправляется

| `event`            | Момент                                                                 |
|--------------------|------------------------------------------------------------------------|
| `TRACK_CHANGED`    | Сменился трек (в т.ч. старт нового).                                   |
| `PLAYBACK_STATE`   | Изменилось play/pause или режим (shuffle).                            |
| `POSITION`         | Heartbeat позиции раз в 1 с во время воспроизведения.                 |
| `STOPPED`          | Воспроизведение остановлено, текущий трек сброшен.                    |

### Extras

| Ключ            | Тип       | Описание                                  |
|-----------------|-----------|-------------------------------------------|
| `event`         | `String`  | Одно из значений выше.                    |
| `title`         | `String?` | Название трека.                           |
| `artist`        | `String?` | Исполнитель.                              |
| `album`         | `String?` | Альбом.                                   |
| `uri`           | `String?` | `content://` URI исходного файла.          |
| `durationMs`    | `Long`    | Длительность, мс.                         |
| `positionMs`    | `Long`    | Текущая позиция, мс.                      |
| `isPlaying`     | `Boolean` | Идёт ли воспроизведение.                  |
| `shuffle`       | `Boolean` | Включён ли случайный порядок.             |
| `index`         | `Int`     | Индекс трека в плейлисте (-1, если нет).  |
| `playlistSize`  | `Int`     | Размер плейлиста воспроизведения.         |
| `sessionId`     | `String`  | Идентификатор сессии (для сопоставления). |
| `timestampMs`   | `Long`    | Время отправки, мс (`System.currentTimeMillis()`). |

### Как слушать

Неявные broadcast-ы не доставляются в ресиверы, объявленные в манифесте, начиная с Android 8
(API 26). Слушатель обязан регистрировать ресивер в рантайме, а на Android 14 (API 34)+ —
передавать флаг экспорта.

```kotlin
val filter = IntentFilter("erech14.freemusical.app.action.TRACK_STATE")
val receiver = object : BroadcastReceiver() {
    override fun onReceive(context: Context, intent: Intent) {
        val event = intent.getStringExtra("event") ?: return
        val title = intent.getStringExtra("title")
        val artist = intent.getStringExtra("artist")
        // ...
    }
}

if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU) {
    ContextCompat.registerReceiver(
        context, receiver, filter, ContextCompat.RECEIVER_EXPORTED
    )
} else {
    context.registerReceiver(receiver, filter)
}
```

Ресивер работает, пока жив процесс слушателя; для фонового приёма запускайте foreground-сервис.

> Примечание: системный UI (локскрин, шторка, Bluetooth, Android Auto) читает данные о треке
> из `MediaSession`, а не из этого broadcast-а.

## Включение интеграций

И broadcast, и HTTP-сервер **по умолчанию выключены**, чтобы не расходовать ресурсы.
Включаются независимо друг от друга в **Настройки → Broadcast и HTTP**:

- тумблер **Broadcast API** — системный broadcast (раздел выше);
- тумблер **HTTP-сервер** — локальный HTTP-сервер (раздел ниже);
- поле **порт** — порт HTTP-сервера, по умолчанию `31414` (1024–65535), применяется кнопкой «Применить».

Настройки сохраняются и применяются автоматически при следующем запуске воспроизведения.

## HTTP API (текущий трек)

Помимо broadcast, те же данные о текущем треке можно получать по HTTP. Сервер слушает
**только локальный IP** устройства (Wi-Fi, site-local IPv4), то есть доступен из локальной
сети и не публикуется наружу. Порт по умолчанию — `31414`.

Базовый адрес, например: `http://192.168.0.5:31414/`

### Эндпоинты

| Метод и путь     | Формат              | Описание                                                        |
|------------------|---------------------|-----------------------------------------------------------------|
| `GET /status`    | `application/json`  | Мгновенный снимок состояния текущего трека.                    |
| `GET /events`    | `text/event-stream` | Поток Server-Sent Events с теми же событиями, что и broadcast. |

Поля JSON в `/status` совпадают с extras broadcast. Отличие только в поле `event`:
у снимка оно равно `STATUS` (мгновенный снимок, а не событие).

```bash
# Снимок текущего состояния
curl http://192.168.0.5:31414/status

# Поток событий (Ctrl+C для выхода)
curl -N http://192.168.0.5:31414/events
```

### Формат SSE

Каждое событие — строка `data:` с тем же JSON, что и `/status`, но с реальным типом события:

```
retry: 3000

data: {"event":"TRACK_CHANGED","title":"...","isPlaying":true,...}

data: {"event":"POSITION","positionMs":12000,...}

: keep-alive
```

События: `TRACK_CHANGED`, `PLAYBACK_STATE`, `POSITION` (раз в секунду), `STOPPED` —
как и у broadcast. При подключении сразу приходит текущий снимок.
